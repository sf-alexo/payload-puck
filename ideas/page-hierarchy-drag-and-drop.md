# Page Hierarchy Drag-and-Drop Plan

## Goal
Add drag-and-drop functionality to the page hierarchy panel in the admin (`/admin/collections/pages`) to allow reordering and/or reparenting pages.

## Current State
- `src/components/PagesHierarchyPanel.tsx` is a **server component** that renders a static nested tree
- Pages have `parent` (self-referencing relationship) and `order` fields
- `src/collections/Pages.ts` has a `beforeChange` hook that:
  - Forces Home page to have no parent
  - Defaults all other pages to Home as parent when none is set
  - Prevents self-parenting

## Required Changes

### 1. Split Server/Client Components
**Why:** Server components can't handle pointer events. Drag-and-drop requires a client component.

**Server component** (`PagesHierarchyPanel.tsx`):
- Keep as a server component
- Fetch pages via `payload.find()`
- Serialize to plain array: `{ id, title, slug, parent (as id), order, status }`
- Render new client component with this data

**New client component** (`PagesHierarchyTree.tsx`):
- `'use client'` directive
- Owns all interactivity and state
- Renders the tree with DnD library
- Handles drop events and persistence

### 2. Add Dependencies
Choose one based on scope:

**Option A: Reorder siblings only**
```bash
pnpm add @dnd-kit/core @dnd-kit/sortable @dnd-kit/utilities
```
- Simpler implementation
- Only reorders pages within the same parent
- Writes `order` field only

**Option B: Full tree (reorder + reparent)**
```bash
pnpm add dnd-kit-sortable-tree @dnd-kit/core
```
- More powerful: can drag pages between parents
- Handles indentation, collapse, drop-as-child
- Writes both `parent` and `order` fields
- More complex state/diff logic

### 3. Implementation Details

#### Data Structure
```typescript
interface PageNode {
  id: number
  title: string
  slug: string
  parent: number | null
  order: number
  status: string
  children: PageNode[]
}
```

#### Persistence Logic
On drop:
1. Compute new tree from DnD library output
2. Diff old vs new tree to find changed nodes
3. For each changed node, PATCH via Payload REST API:
```typescript
await fetch(`/api/pages/${node.id}`, {
  method: 'PATCH',
  headers: { 'Content-Type': 'application/json' },
  credentials: 'include',
  body: JSON.stringify({ parent: node.parent, order: node.order }),
})
```
4. Call `router.refresh()` to re-render server component with fresh data

#### Important Constraints
- **Home stays root:** Disable dragging Home or reject drops that try to give it a parent. The hook will override anyway, but blocking in UI avoids confusing snap-backs.
- **Cycle prevention:** Block dropping a page into one of its own descendants (current guard only blocks direct self-parenting).
- **Order persistence:** Reordering means rewriting sequential `order` values (0,1,2…) across all affected siblings, not just the moved item.

### 4. Import Map Update
After adding the client component:
```bash
pnpm payload generate:importmap
```
This updates `src/app/(payload)/admin/importMap.js` to include the new component.

## Effort Estimate
- **Reorder-only:** ~1 small client component + 1 dep. Low effort/risk.
- **Full reparenting tree:** More state/diff logic + cycle handling + Home-lock UX. Moderate effort.
